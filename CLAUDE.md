# Vedaai grader

Answer-sheet grader. Upload a printed question paper plus one student's handwritten
sheet; every question is extracted in printed order, every answer is located on the
page, and clicking a question highlights the region that answers it.

`README.md` is the source of truth for architecture, measured accuracy, and known
limitations. Read it before proposing any change to the pipeline. It is honest about
what is broken and about figures that were previously wrong, so do not restate its
numbers from memory.

## The invariant that everything depends on

**The model never emits coordinates. It emits line ids, and code computes the
geometry.** Zero-shot VLM grounding caps around 55% on HG-Bench for this exact task,
so any change that asks a model for a bounding box, a pixel offset, or a rectangle is
wrong by construction. Geometry comes from transcription line boxes and from the
OpenCV ink mask, never from a model.

The coordinate contract lives once in `packages/contracts` and is generated into both
languages: normalized `[0,1]` floats, origin top-left, `page` 0-indexed, relative to
the page as rendered. Never hand-edit generated output in `packages/generated`. Change
the contract and re-run codegen.

## Layout

```
apps/web              Next.js: upload, waiting, mapping surface
apps/api              FastAPI + the pipeline
packages/contracts    the coordinate contract, source of both language bindings
packages/generated    codegen output, never edit by hand
packages/evals        golden set, synthetic generator, metrics
tooling/scripts       sample and paper builders, corpus loop, engine comparison
deploy                container, IAM, deploy script
```

Geometry, hit-testing and mapping logic in the web app live in `apps/web/lib/`, with
no React and no DOM. Keep it that way; it is why the UI can be rebuilt without
touching the logic.

## Commands

Needs Node 20, pnpm, Python 3.13, uv. Use pnpm, never npm or yarn.

```bash
pnpm install
pnpm turbo codegen      # contracts -> TypeScript. Run after any contract change
pnpm dev                # web :3000, API :8000
pnpm turbo test         # unit tests, both languages
pnpm turbo eval         # extraction, mapping, IoU against the golden set
python tooling/scripts/audit_ui.py <submission-id>   # layout faults, 6 viewports
```

Everything runs with no API keys. Handwriting recognition needs
`OCR_ENGINE=textract` with AWS credentials, or `uv sync --extra ocr-local`. Marking
needs `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`.

## Conventions

- Any claim about accuracy must come from a fresh run **in this session**, and two
  measurements being compared must come from the same session. The eval harness now
  loads `.env` and fails when its scorer is not the service's, but a figure measured
  hours earlier has already failed to reproduce at the same commit — the scorer
  depends on a hosted embedding service, so the golden set is not a closed system.
- `pnpm turbo eval` measures where answers are. `pnpm --filter @vedaai/evals gate`
  measures whether the marks are right, and it costs paid calls. Run it before any
  commit that touches marking, and with `--passes 3` before believing a change of one
  or two marks.
- The golden set is generated by the same code that parses it, so a 100% extraction
  score does not mean real papers work. Validate parser changes against a real paper,
  not only the synthetic set.
- A false `unanswered` is the worst error this product can make. Never collapse the
  four absence states (`unanswered`, `ocr_failed`, `not_required`, `pages_missing`)
  into one threshold.
- Report placement accuracy and highlight IoU separately. They move for unrelated
  reasons and the two highlight metrics pull against each other by construction.
- `deploy/` and IAM are mine. Do not run `deploy/deploy.sh` or apply infrastructure.
  The live deploy is behind `ACCESS_CODE`; never remove or weaken that gate.
- Uploads are untrusted input. Read the "Untrusted input" section of the README
  before changing anything in the ingest path.
